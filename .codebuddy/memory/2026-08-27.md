  2. 新增 `_is_ignored_path(filepath)`：按 `PROJECT_DIR` 起的完整相对路径逐级判断，任一层级命中
     `IGNORE_NAMES` 或以 `.` 开头（隐藏项）即排除。
  3. `should_include` 与 `build_all_loader` 改用 `_is_ignored_path`。
- **验证**：`python packed.py 4.0.4 all` 重新打包，22 版本全部成功；44 个产物（22 zip + 22 jar）
  经脚本扫描均无上述多余条目。

## 修复：配方归档路径含版本号前缀 + jar 内配方重复写入

- **用户要求**：配方路径只应有命名空间（`data/extrarecipe/recipe/<namespace>/...`），不应有版本编号目录。
- **问题 1**：`get_recipe_archive_path` 把源目录名（如 `4-1.13-1.14.4`）原样拼入路径。
  → 修复：函数开头剥掉开头的版本目录名（`if _is_version_dir(parts[0]): parts = parts[1:]`）。
- **问题 2**：`build_all_loader` 的 rglob 循环与 `add_recipe_files` 各写一遍版本目录里的配方，
  导致 jar 内同一配方写两次（178 个重复，字节相同）。
  → 修复：rglob 循环增加 `if _is_version_dir(filepath.relative_to(PROJECT_DIR).parts[0]): continue`，
  配方统一由 `add_recipe_files` 写入。
- **验证**：全量 `4.0.4 all` 重打包 22 版本全成功；45 个产物（含新增 jar）共 4272 配方条目，
  **0 重复、0 版本号前缀**，命名空间为 `ae2/ironchest/minecraft/twilightforest`。
- 另：之前误把 `CODEBUDDY.md` 也加进了 `IGNORE_NAMES`（用户要求基本文件即可）。

## 修复：1.21.2+ (pack_format>=57) 有序合成 key 被 list() 误转成键列表

- **现象**：高版本产物（57/61/71/80/81/88/94/101/107）shaped 配方 `key` 字段类型变成 list，
  只剩字符键 `["#","$","*"]`，丢失映射值 → 配方损坏。用户看到的是 `output` 下解压残留的
  无扩展名目录（旧结构，带版本号前缀），以及这些旧 jar。
- **根因**：`convert_recipe_for_1_21` 第 382 行 `_convert_tag_prefixes(items=list[Any](_convert_key_to_string(...)))`
  把 `_convert_key_to_string` 返回的 dict 传给 `list()`，dict 被转成 keys 列表。
  `_convert_key_to_string` 本身逻辑正确（返回 `{char: 字符串值}` dict）。
- **修复**：改为 `{char: _ensure_tag_prefix(value=v) for char, v in _convert_key_to_string(data["key"]).items()}`
  （pack_format>=57 分支保持 dict，仅对值补 tag 前缀）。
- **验证**：全量 `4.0.4 all` 重打包 22 版本成功；44 个产物全部 shaped 配方 key 异常=0。
  样例 `acacia_sapling` 修复后 key = `{"#":"minecraft:acacia_leaves","$":"minecraft:bone_meal","*":"minecraft:dead_bush"}`。
- **注意**：扫描产物时低版本用 `recipes`(复数) 目录、高版本用 `recipe`(单数)，验证脚本需同时覆盖两者。
- 已删除 `output/` 下解压遗留的无扩展名旧目录 `[All Loader]Extra Recipe-4.0.4-107.1/`。
